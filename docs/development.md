# Development

A personal link-in-bio page, built with [Hugo](https://gohugo.io) and the
[banyan](https://github.com/tiennm99/banyan) theme.

## How it works

The profile lives in one file, [`config/_default/params.yml`](../config/_default/params.yml):
name, tagline, bio, avatar and links. One Hugo build renders it twice:

- `index.html`, the page;
- `README.md`, the same profile as Markdown, served at `/README.md`.

Push to `main` and GitHub Actions builds the site, deploys it to GitHub Pages,
and copies the built `README.md` to the repo root. When that file changed, the
workflow commits it as `github-actions[bot]`, so pull before your next edit.
Do not edit the root `README.md` by hand: the next build overwrites it.

## Local development

Requires Hugo ≥ 0.154.5 (the version in Ubuntu 26.04 LTS) and Go, which Hugo
uses to fetch the theme module.

```bash
hugo server          # http://localhost:1313
hugo --gc --minify   # build to ./public
```

A local build uses `baseURL: /`, so its `public/README.md` has root-relative
links. Only the CI build, with the Pages URL, is copied to the repo root.

## Theme

The theme is the Hugo module `github.com/tiennm99/banyan`, pinned in `go.mod`.
To update it:

```bash
hugo mod get -u github.com/tiennm99/banyan
hugo mod tidy
```

## Deployment

Every push to `main` deploys to GitHub Pages. The workflow turns Pages on by
itself on its first run (`actions/configure-pages` with `enablement: true`).
The build job grants itself `contents: write` to commit the README, so the
repo's default workflow permissions can stay read-only.

Custom domain (optional): add a `static/CNAME` file holding the domain; Hugo
copies it into the site.

### Base URL

`config/_default/hugo.yml` sets `baseURL: /`, so a plain `hugo` build serves
from the domain root. The Pages workflow overrides it with the Pages URL
(`https://<owner>.github.io/iammiti99/`), so only that host gets the
`/iammiti99/` subpath.

### Other hosts (Cloudflare Pages, Netlify, Vercel)

| Setting | Value |
|---|---|
| Build command | `hugo --gc --minify` |
| Output directory | `public` |
| Env `HUGO_VERSION` | `0.154.5` or newer |
| Go | needed to fetch the theme module; set the host's Go version env if its image lacks Go |
| Env `HUGO_BASEURL` (optional) | the site's full URL, e.g. `https://<project>.pages.dev/` |

Without `HUGO_BASEURL` the site is served from the host's root URL, but
`og:image`, the canonical link and the links in `README.md` stay relative. Set
it so social link previews get absolute URLs.

## Project layout

```
config/_default/params.yml   # the profile — edit this
config/_default/hugo.yml     # site config and output formats
content/_index.md            # placeholder so Hugo renders the home page
static/images/               # avatar
go.mod, go.sum               # Hugo module: pins the banyan theme version
.github/workflows/deploy.yml # build, deploy, README sync
README.md                    # generated by CI — do not edit
public/                      # build output (gitignored)
```
